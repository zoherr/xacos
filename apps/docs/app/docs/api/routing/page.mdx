# API File Convention

XAOCS uses a highly intuitive, file-based routing convention for backend APIs. E.g., you never need to manually register routes in a central router file.

## `*.api.ts` Files

Any file in the `api/` directory matching the `*.api.ts` naming convention is automatically discovered and mounted by the framework.

The URL prefix is automatically derived from the filename:
- `api/user.api.ts` → mounts at `/api/user`
- `api/auth.api.ts` → mounts at `/api/auth`
- `api/index.api.ts` → mounts at `/api`

## Example API Route File

```typescript
// api/user.api.ts
import { XRouter } from '@xacos/core';

export const router = new XRouter();

// GET /api/user
router.get('/', async (req, res) => {
  return res.json({ users: [] });
});

// POST /api/user
router.post('/', async (req, res) => {
  return res.status(201).json({ success: true });
});
```

## Dynamic Route Segments

You can define dynamic route parameters using bracket notation in your filenames:
- `api/posts/[id].api.ts` → mounts at `/api/posts/:id`

Inside your route handlers, access the parameter via `req.params`:

```typescript
// api/posts/[id].api.ts
import { XRouter } from '@xacos/core';

export const router = new XRouter();

router.get('/', async (req, res) => {
  const { id } = req.params;
  return res.json({ postId: id });
});
```
